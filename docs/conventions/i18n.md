# i18n Conventions

앱에서 작성하는 사용자용 문구는 ARB 파일에 두고 `S.of(context)`로 가져와요. ViewModel은 `BuildContext`에 의존하지 않으며 오류 코드와 서버 메시지를 보관할 수 있어요. 화면이 상황에 맞는 번역을 선택해요. 새 키를 추가하면 한국어·영어 ARB와 생성 코드, 키 일치 테스트를 함께 확인해요.

---

## 파일 구조

```text
lib/core/i18n/
├── app_ko.arb                  # 템플릿 언어 (원문)
├── app_en.arb                  # 영어 번역
├── app_localizations.dart      # 자동 생성 — S 클래스
├── app_localizations_ko.dart   # 자동 생성
└── app_localizations_en.dart   # 자동 생성
```

설정은 `l10n.yaml` 에 있어요:

```yaml
arb-dir: lib/core/i18n
template-arb-file: app_ko.arb        # 한국어를 원문으로
output-localization-file: app_localizations.dart
output-class: S                       # S.of(context) 로 접근
nullable-getter: false                # S.of(context)의 반환 타입을 non-null로 생성해요.
```

---

## 워크플로우: 새 문자열 추가

기존에 같은 뜻의 키가 있으면 재사용해요. 예를 들어 로그인 버튼에는 이미 `login`이 있어요. 아래는 파생 앱에 지출 추가 액션을 새로 만드는 예제예요.

1. **`app_ko.arb`에 키를 추가해요.**
   ```json
   {
     "expenseAdd": "지출 추가",
     "@expenseAdd": {
       "description": "지출 목록에서 새 지출을 추가하는 액션"
     }
   }
   ```

2. **`app_en.arb`에 같은 키를 추가해요.**
   ```json
   {
     "expenseAdd": "Add expense"
   }
   ```

3. **생성 코드를 갱신해요.**
   ```bash
   flutter gen-l10n
   ```

4. **화면에서 사용해요.**
   ```dart
   Text(S.of(context).expenseAdd)
   ```

> 번역이 빠졌다고 항상 컴파일이 실패하지는 않아요. [`arb_parity_test`](https://github.com/storkspear/template-flutter/blob/main/test/core/i18n/arb_parity_test.dart)는 한국어·영어 키의 일치와 빈 문자열을 검사해요. 양쪽 ARB를 갱신하고 생성 뒤 이 테스트도 확인해요.

## ARB 파일 포맷

### 기본 키

```json
{
  "@@locale": "ko",
  "login": "로그인",
  "signUp": "회원가입"
}
```

### 설명 (번역가용)

아래는 앞에서 추가한 키의 설명이에요.

```json
{
  "@expenseAdd": {
    "description": "지출 목록에서 새 지출을 추가하는 액션"
  }
}
```

### 파라미터 치환

이하의 `welcomeMessage`, `itemCount`, `lastUpdated`는 형식을 설명하는 새 키 예제예요. 실제 템플릿에 있는 키는 아니므로 사용하려면 한국어·영어 ARB 양쪽에 정의하고 생성 코드를 갱신해야 해요.
```json
{
  "welcomeMessage": "안녕하세요, {name}!",
  "@welcomeMessage": {
    "description": "홈 화면 인사말",
    "placeholders": {
      "name": {"type": "String"}
    }
  }
}
```

자동 생성되는 코드는 이래요:
```dart
String welcomeMessage(String name) => '안녕하세요, $name!';
```

### 복수형 (ICU format)

```json
{
  "itemCount": "{count, plural, =0{항목 없음} =1{1개 항목} other{{count}개 항목}}",
  "@itemCount": {
    "placeholders": {
      "count": {"type": "int"}
    }
  }
}
```

이렇게 사용해요:
```dart
Text(S.of(context).itemCount(5))  // "5개 항목"
Text(S.of(context).itemCount(0))  // "항목 없음"
```

<a id="날짜--숫자-포맷"></a>

### 날짜 · 숫자 포맷

```json
{
  "lastUpdated": "마지막 업데이트: {date}",
  "@lastUpdated": {
    "placeholders": {
      "date": {
        "type": "DateTime",
        "format": "yMMMd"
      }
    }
  }
}
```

## 키 명명 규칙

네이밍 접두사로 용도를 구분해요. [`naming.md`](./naming.md#i18n-키-명명) 를 참조하세요.

| 접두사 | 예시 | 용도 |
|--------|------|------|
| (없음) | `login` · `signUp` · `settings` | 일반 UI 텍스트 |
| `validation` | `validationEmailRequired` | 폼 검증 에러 |
| `error` | `errorTimeout` · `errorNetworkUnavailable` | 네트워크 · 앱 에러 |
| `toast` | `toastBackPressExit` | 스낵바 · 토스트 |
| `relativeTime` | `relativeTimeMinutes` · `relativeTimeDays` | 상대 시간 |
| (없음) | `confirm` · `cancel` · `retry` | 확인 · 취소 류 |

### 키 명명 관용

- **짧고 명확하게**: `loginButton` 대신 `login` 을 써요 (맥락이 화면에서 드러나요)
- **축약 피하기**: `btn` · `msg` · `err` 는 금지예요. `button` · `message` · `error` 로 풀어써요
- **계층 표현 시 camelCase**: `errorNetworkUnavailable` 로 써요 (`error_network_unavailable` 이 아니에요)
- **중복 방지**: 동일 표현이 여러 화면에 쓰이면 **하나의 키** 로 합쳐요 — `ok`, `cancel`, `retry` 등

## Screen 에서 사용

앞의 예제 키를 정의하고 생성한 뒤에는 다음처럼 사용할 수 있어요. 예제 화면의 입력값은 생성자로 받아요.

```dart
class LocalizationExampleScreen extends StatelessWidget {
  const LocalizationExampleScreen({
    super.key,
    required this.userName,
    required this.itemCount,
    required this.updatedAt,
  });

  final String userName;
  final int itemCount;
  final DateTime updatedAt;

  @override
  Widget build(BuildContext context) {
    final s = S.of(context);
    return Scaffold(
      body: Column(
        children: [
          Text(s.welcomeMessage(userName)),
          Text(s.itemCount(itemCount)),
          Text(s.lastUpdated(updatedAt)),
        ],
      ),
    );
  }
}
```

<a id="final-s--sofcontext-관용"></a>

### `final s = S.of(context)` 관용

화면마다 `S.of(context).xxx` 를 여러 번 호출하게 돼요. `final s = S.of(context)` 로 alias 하면 코드가 짧아져요. 모든 Screen 에서 이 관용을 권장해요.

## ViewModel 은 i18n 의존 금지

ViewModel은 `BuildContext`를 받지 않고 오류 코드와 필요한 서버 메시지를 상태에 저장해요. 번역과 화면 표시 정책은 Screen에 둬요. 아래는 비동기 작업의 catch 블록 예제예요.

```dart
catch (e) {
  if (!ref.mounted) return;
  state = state.copyWith(
    isLoading: false,
    errorCode: safeErrorCode(e, fallbackCode: AuthLocalErrorCode.login),
    errorMessage: safeErrorMessage(e),
  );
}
```

인증 화면은 공통 helper로 표시 문구를 정해요. 서버 메시지와 번역 중 어느 것을 우선하는지는 [오류 처리 규칙](./error-handling.md#screen-에서-i18n-변환)에 있어요.

```dart
final errorText = resolveAuthErrorText(
  state.errorMessage,
  state.errorCode,
  S.of(context),
);
// Column.children 같은 위젯 목록 안에서 사용해요.
if (errorText != null) Text(errorText),
```

자체 오류 매핑을 추가할 때는 알 수 없는 코드의 기본 문구도 반환해야 해요.

자세한 건 [`error-handling.md`](./error-handling.md#screen-에서-i18n-변환) 을 참조하세요.

## MaterialApp 설정

```dart
// lib/app.dart 발췌
MaterialApp.router(
  title: AppConfig.instance.appSlug,
  theme: AppTheme.light(),
  darkTheme: AppTheme.dark(),
  localizationsDelegates: S.localizationsDelegates,  // Material/Widgets/Cupertino delegate 포함
  supportedLocales: S.supportedLocales,              // ARB에서 생성한 지원 언어
  routerConfig: _appRouter.router,
)
```

---

## 새 언어 추가

1. `app_{locale}.arb` 파일 추가 (예: `app_ja.arb`)
2. 모든 키 번역
3. `flutter gen-l10n`
4. `S.supportedLocales` 에 새 locale 이 포함됐는지 확인

`MaterialApp`은 생성된 `S.supportedLocales`를 사용하므로 새 언어 목록을 직접 적을 필요는 없어요. 다만 현재 키 일치 테스트는 한국어·영어만 비교하므로 새 언어를 검사 대상에 추가해야 해요. 번역 누락, 날짜·숫자 표시, 글리프와 긴 문구의 레이아웃도 확인해요.

## 자주 하는 실수

<a id="-하드코딩"></a>

### ❌ 하드코딩

```dart
// 금지
Text('로그인')
Text('이메일을 입력해주세요')
```

**올바르게**:
```dart
Text(S.of(context).login)
Text(S.of(context).validationEmailRequired)
```

<a id="-한쪽-arb-에만-키-추가"></a>

### ❌ 한쪽 ARB 에만 키 추가

```json
// app_ko.arb 에만 추가
{
  "newKey": "새 기능"
}
// app_en.arb에는 없음 → arb_parity_test 실행 시 키 불일치로 실패해요.
```

**올바르게**: 양쪽에 추가하고 `flutter gen-l10n` 을 실행해요.

<a id="-gen-l10n-안-돌리고-사용-시도"></a>

### ❌ `gen-l10n` 안 돌리고 사용 시도

```dart
Text(S.of(context).newKey)  // ← 정의 안 된 키 → 컴파일 에러
```

**올바르게**: ARB 수정 직후 항상 `flutter gen-l10n` 을 돌려요.

<a id="-viewmodel-에서-sofcontext"></a>

### ❌ ViewModel 에서 `S.of(context)`

```dart
// 금지
Future<void> doSomething(BuildContext context) async {
  state = state.copyWith(message: S.of(context).success);
}
```

**올바르게**: ViewModel은 코드와 필요한 서버 메시지를 저장하고, Screen에서 번역과 표시 문구를 결정해요.

<a id="-파라미터-치환-없이-string-concat"></a>

### ❌ 파라미터 치환 없이 String concat

```json
// 금지
{
  "welcome": "안녕하세요, "
}
```

```dart
Text(S.of(context).welcome + userName)  // 영어엔 " " 앞에, 한국어엔 ", " 뒤에 등 순서 문제
```

**올바르게**: `{name}` 파라미터로 치환해요.
```json
{
  "welcome": "안녕하세요, {name}!",
  "@welcome": {"placeholders": {"name": {"type": "String"}}}
}
```
